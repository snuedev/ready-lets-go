# Wayfinding

Big, foggy efforts are charted as a **map**: a single Trello card holding the destination, the decisions made so far, and the fog not yet specified, with one child ticket per open decision. The board is canonical — a map is worked on and edited constantly, and a copy in this repo would rot.

What lands here instead is what each map produces: architectural decisions in [`docs/adr/`](./adr/), domain vocabulary in [`CONTEXT.md`](../CONTEXT.md), and specs beside this file.

`docs/issue-tracker.md` has the Trello conventions.
